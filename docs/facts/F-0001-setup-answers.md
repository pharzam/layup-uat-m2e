2. `Q-001` A carriage return before a line feed is part of the line and is counted as a character, like any other code point. A line feed alone ends an empty line, which counts as one line. An empty file has zero lines, zero words and zero characters. — by idea-owner; source https://github.com/pharzam/layup-uat-m2e/issues/1#issuecomment-6323442283; the question: Does a carriage return before the line feed (CRLF) belong to the line or count as a character, and does an empty line (a line feed alone) count as a line?
3. `Q-002` Flags may be combined. Each flag selects its count; with several flags, tally prints the selected counts in the fixed order lines, words, characters, whatever the order of the flags on the command line. With no flag it prints all three. — by idea-owner; source https://github.com/pharzam/layup-uat-m2e/issues/1#issuecomment-6323442283; the question: May the flags be combined (e.g. `-l -w`), and if so in what order are the selected counts printed — fixed lines/words/characters order or the order the flags are given?
4. `Q-003` The row for standard input has no name: it ends after the counts. The name `-` is not accepted as standard input: tally treats it as a file named `-`. — by idea-owner; source https://github.com/pharzam/layup-uat-m2e/issues/1#issuecomment-6323442283; the question: What name, if any, is printed in the output row when the text comes from standard input, and does a file name of `-` mean standard input?
5. `Q-004` The total row is the sum of the selected counts of the files that were counted without an error, followed by the word `total`, in the layout of the other rows. A file that cannot be read, or is not valid UTF-8, adds nothing to the total. — by idea-owner; source https://github.com/pharzam/layup-uat-m2e/issues/1#issuecomment-6323442283; the question: What does the total row hold — the summed selected counts followed by the word `total` — and does it include or exclude files that could not be read or were not valid UTF-8?
6. `Q-005` No row is printed for a file that is not valid UTF-8: it is skipped entirely, like an unreadable file, with a message on standard error that gives its name, and the exit code 1 at the end. The remaining files are still counted. The message does not give the byte offset. — by idea-owner; source https://github.com/pharzam/layup-uat-m2e/issues/1#issuecomment-6323442283; the question: Is a row of counts still printed for a file that is not valid UTF-8, are the remaining files still counted, and should the message also give the byte offset of the first invalid sequence?
7. `Q-006` A file is not text exactly when it is not valid UTF-8 (rule 6). A directory is an unreadable file: tally prints a message on standard error with its name and the reason, adds no row, and ends with the exit code 1. — by idea-owner; source https://github.com/pharzam/layup-uat-m2e/issues/1#issuecomment-6323442283; the question: How does tally decide that a file is "not text" or a directory, and what message and exit code does it give for one — is it the same as an unreadable file?
8. `Q-007` An unknown flag or wrong usage prints a usage message on standard error, counts nothing, and ends with the exit code 2. — by idea-owner; source https://github.com/pharzam/layup-uat-m2e/issues/1#issuecomment-6323442283; the question: What happens and which exit code results for an unknown flag or wrong usage — a usage message on standard error with exit code 1, 2, or something else?
