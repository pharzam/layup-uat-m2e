Q-001: A carriage return before a line feed is part of the line and is counted as a character, like any other code point. A line feed alone ends an empty line, which counts as one line. An empty file has zero lines, zero words and zero characters.
Q-002: Flags may be combined. Each flag selects its count; with several flags, tally prints the selected counts in the fixed order lines, words, characters, whatever the order of the flags on the command line. With no flag it prints all three.
Q-003: The row for standard input has no name: it ends after the counts. The name `-` is not accepted as standard input: tally treats it as a file named `-`.
Q-004: The total row is the sum of the selected counts of the files that were counted without an error, followed by the word `total`, in the layout of the other rows. A file that cannot be read, or is not valid UTF-8, adds nothing to the total.
Q-005: No row is printed for a file that is not valid UTF-8: it is skipped entirely, like an unreadable file, with a message on standard error that gives its name, and the exit code 1 at the end. The remaining files are still counted. The message does not give the byte offset.
Q-006: A file is not text exactly when it is not valid UTF-8 (rule 6). A directory is an unreadable file: tally prints a message on standard error with its name and the reason, adds no row, and ends with the exit code 1.
Q-007: An unknown flag or wrong usage prints a usage message on standard error, counts nothing, and ends with the exit code 2.
Q-008: The reference is any computer with 4 cores and a solid-state disk, with the file already in the cache of the operating system, for a file of 10 MiB of ASCII text with lines of about 80 characters. The time is the elapsed time of the whole process, from its start to its exit.
Q-009: Yes: the limit is the peak heap during the run, not the heap at the end. It is measured by sampling the heap in use (`runtime.ReadMemStats`, `HeapAlloc`) every 10 milliseconds during the count and taking the largest value.
Q-010: Yes, the split is required: the counting package is a package `count` of the same Go module, separate from the package `main` of the command, and it holds the functions that count the lines, the words and the characters of a reader. The 90 percent target covers the package `count` only.
